# Connect the root POS to Supabase

## Objective

Use Supabase Auth for account creation and sign-in in the deployed root `index.html`, while keeping the current IndexedDB/localStorage workspace usable offline and synchronizing a complete owner-scoped snapshot when online.

## Safety constraints

- Preserve existing local records and IDs; the first authenticated device must be able to seed a missing cloud workspace from its current local snapshot.
- Never replace a non-empty local or remote copy without a clear, explicit user choice.
- Keep credentials out of browser storage and ship only the public Supabase URL and publishable key.
- Keep all business writes local-first; network or sync failures must not block local operations.
- Restrict remote workspace reads and writes to the authenticated owner with RLS.

## Tasks

1. Add a versioned `workspaces` table and owner-scoped RLS policies in a new Supabase migration.
2. Add Supabase client initialization, email/password sign-up and sign-in, session restore, local sign-out, and offline-session behavior to the root app.
3. Add conflict-aware bootstrap and debounced full-snapshot sync after local saves, with visible sync status and retry path.
4. Verify migration SQL and root JavaScript/build behavior; document the migration and environment assumptions.

## Implementation notes

- Added `public.pos_workspaces`, storing one complete JSONB snapshot per Supabase Auth user; this does not write into the separate normalized sales/order tables from migrations `001` and `002`.
- Added an offline app-shell service worker. Supabase endpoints are never cached; authenticated data remains local-first and is requested from Supabase only while online.
- `supabase/README.md` documents setup, snapshot shape, and the first-sign-in flow.
